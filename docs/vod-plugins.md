# Плагины: источники фильмов

🇬🇧 [English](en/vod-plugins.md)

Каналы плеер берёт из плейлиста M3U. А фильмы и сериалы — из **источника**. Источник — это **плагин**:
один файл JavaScript, который умеет разговаривать с конкретным сервисом (видеопорталом провайдера,
домашней медиатекой и так далее).

Плагин — это переводчик. Сервис отвечает по-своему, плеер понимает только один формат, плагин
переводит из одного в другое. Всё, что видно на экране — ленты, поиск, карточка фильма, избранное,
рейтинги — рисует сам плеер; плагин экранов не касается, он только отдаёт данные.

Источников может быть сколько угодно, в том числе ни одного: тогда в плеере просто нет раздела с
фильмами, а каналы работают как обычно.

---

# Часть 1. Как поставить готовый плагин

Всё делается на странице дополнения в Home Assistant: боковое меню → **AssisTV** → раздел **«Плагины»**.
Ни Samba, ни перезапусков не нужно.

> 🎬 **Нет своего источника — начните с готового примера.** Плагин
> [Internet Archive](../plugins/archive-org/README.md) показывает классику кино из общественного
> достояния: нуар, фантастику 50-х, немое кино, вестерны. Ключ не нужен — только адрес
> `https://archive.org` в настройках.

## Шаг 1. Установить

Есть два способа:

- **По ссылке.** Вставьте адрес файла плагина (`https://…/plugin.js`) и нажмите «Установить по ссылке».
- **Файлом.** Нажмите «загрузить файл с компьютера» и выберите `.js`. Так ставят плагины из закрытых
  репозиториев: по ссылке Home Assistant их не скачает.

Дополнение проверит файл. Если это не плагин или в нём ошибка, вы увидите, что не так. Новый плагин
появляется в списке **выключенным**.

> ⚠️ **Плагин — это программа.** Он работает в песочнице дополнения: без доступа к файлам и к самому
> Home Assistant. Но ваши ключи и пароли от источника у него будут. Ставьте только плагины, которым
> доверяете.

## Шаг 2. Настроить и включить

В карточке плагина:

1. **Название в меню** — его увидите на телевизоре (например «Моя медиатека»).
2. **Поля настроек** — адрес сервиса, ключ, логин. Какие поля нужны, плагин сообщает сам. Пароли на
   странице не показываются: пустое поле оставляет прежнее значение.
3. **Включён** — поставьте галочку.
4. **Работать на телевизоре без аддона** — по желанию, см. ниже.
5. **Сохранить.**

Телевизоры подхватят источник сами, приложение перезапускать не нужно.

## Работать на телевизоре без аддона

Обычно плагин работает **только в дополнении**: телевизор просит у дополнения списки и карточки,
а ключи источника на телевизор не уходят.

Минус: если Home Assistant недоступен, фильмы не открываются. Отметка «Работать на телевизоре без
аддона» это исправляет. Дополнение отдаёт телевизорам копию плагина вместе с его настройками,
и без дополнения телевизор ходит к источнику сам. Ключи при этом хранятся на телевизорах, поэтому
включайте отметку только для плагинов, которым доверяете.

## Обновить и удалить

- **Обновить** — установите новую версию тем же способом, настройки сохранятся.
- **Выключить на время** — снимите «Включён».
- **Удалить** — кнопка «Удалить плагин». Избранное и история просмотра этого источника остаются и
  вернутся, если поставить плагин снова.

## Если что-то пошло не так

| Что видно | В чём дело |
|---|---|
| Нет источника в плеере | Плагин не включён или не заполнено обязательное поле (*) |
| У плагина «ошибка» | Ошибка в самом файле плагина — текст на странице и в журнале дополнения |
| «Это не плагин» при установке | Файл не вызывает `VodSources.register(…)` |
| Фильмы не открываются, когда HA выключен | Не включена отметка «Работать на телевизоре без аддона» |

> До раздела «Плагины» плагины клали в папку `/config/tizen-iptv/plugins/`, а адрес писали строкой
> `тип::[key:…]url` в `playlists`. Так ещё работает: файлы из старой папки видны в разделе, а строка
> при первом запуске сама переносится в настройки плагина. Потом её можно удалить.

# Часть 2. Как написать свой плагин

## Что от плагина требуется

- один файл, без сборки и без библиотек;
- **никаких окон и надписей** — плагин отдаёт только данные, рисует их плеер. Файл выполняется в
  песочнице дополнения (Node.js), а с отметкой «без аддона» — ещё и в браузере телевизора, поэтому
  `document`, `window`, `require` и тому подобного в нём быть не должно;
- в интернет — только через `fetch`; файлов и переменных окружения у плагина нет;
- если сервис требует логин — плагин логинится сам и сам хранит свой токен в памяти; плеер про
  пароли ничего не знает и не спрашивает.

## Скелет

Каждый плагин устроен одинаково:

```js
VodSources.register('example', {          // 'example' — имя источника (латиница, цифры, - и _)
    meta: {                               // манифест: его показывает раздел «Плагины»
        name: 'Моя медиатека', version: '1.0.0', author: 'Я', homepage: 'https://…', api: 1,
        settings: [                       // поля формы настроек; url — адрес сервиса, остальные — в params
            { key: 'url', label: 'Адрес сервиса', required: true },
            { key: 'key', label: 'Ключ', type: 'password' }
        ]
    },
    create(url, params) {                 // url и params — из формы настроек
        const key = params.key || '';     // params — это { key: 'МОЙ_КЛЮЧ' }

        return {
            async root() { … },
            async page(request) { … },
            async details(item) { … },
            searchRequest(root, text) { … },
            filterRequest(requests) { … },
            itemById(localId) { … }
        };
    }
});
```

Без `meta` форма всё равно будет: поля «URL» и «Key». `create` вызывается один раз, когда источник открывают. Всё, что вы в нём заведёте (ключ, токен,
кеш), живёт дальше внутри — это обычное замыкание.

## Что вызывается и когда

| Метод | Когда вызывается | Что должен вернуть |
|---|---|---|
| `root()` | при открытии источника | категории, поиск, фильтры |
| `page(request)` | когда открывают категорию, ищут, листают дальше | страницу элементов |
| `details(item)` | когда открывают карточку фильма | фильм, серии, озвучки |
| `searchRequest(root, text)` | когда ввели текст в поиске | запрос для `page` |
| `filterRequest(requests)` | когда выбрали жанр/год | запрос для `page` |
| `itemById(localId)` | избранное, команда из Home Assistant | элемент для `details` |

## `request` — что это такое

Плеер не знает, как устроен ваш сервис, и знать не хочет. Поэтому он работает так: вы отдаёте ему
вместе с каждой категорией и с каждой «следующей страницей» некий `request` — любой объект, какой
вам удобен. Плеер его **не разглядывает**, он просто вернёт его вам обратно в `page(request)`.

Хотите — кладите туда адрес, хотите — номер страницы, хотите — что угодно ещё:

```js
{ path: '/movies', page: 2 }        // так можно
{ cmd: 'flicks', fid: 17 }          // и так можно
'movies?page=2'                     // строкой тоже можно
```

## Метод `root()` — главная

Вызывается один раз при открытии источника.

**Получает:** ничего.

**Возвращает:**

```js
{
    categories: [                                   // ленты на главной, сверху вниз
        { title: 'Фильмы',  request: { path: '/movies' } },
        { title: 'Сериалы', request: { path: '/series' } }
    ],
    search: { request: { query: '{USERINPUT}' } },  // можно null — см. ниже про поиск
    filters: [                                      // можно [] — тогда кнопок фильтров не будет
        {
            title: 'Жанр',
            items: [
                { title: 'Комедия', request: { genre: 5 } },
                { title: 'Драма',   request: { genre: 8 } }
            ]
        }
    ]
}
```

На экране это превращается в: кнопку «Поиск», кнопки «Жанр: все», «Год: все» и ленты категорий.

`search` вы кладёте для себя — плеер в него не заглядывает, а просто отдаёт вам его обратно в
`searchRequest`. Кнопка «Поиск» на экране есть всегда, даже если вы написали `search: null`; если ваш
сервис искать не умеет, верните из `searchRequest` такой запрос, на который `page` отдаст пустой
список — зритель увидит «Ничего не нашлось».

## Метод `page(request)` — список

Вызывается, когда открывают категорию, ищут, применяют фильтр и когда листают до конца списка.

**Получает:** тот самый `request`, который вы отдали в `root()`, в `searchRequest` или в прошлом
ответе как `nextRequest`.

**Возвращает:**

```js
{
    items: [ …элементы… ],              // см. ниже
    count: 240,                         // всего в категории, для надписи «Фильмы · 240»; можно null
    nextRequest: { path: '/movies', page: 3 }   // следующая страница; null — список кончился
}
```

Догрузка работает сама: как только зритель долистает почти до конца, плеер вызовет `page` с вашим
`nextRequest`. Ничего специально делать не нужно — просто отдавайте его, пока есть что отдавать.

### Элемент списка

```js
{
    type: 'stream',            // 'stream' — фильм или серия, 'multistream' — сериал
    fid: '12345',              // ваш идентификатор: число или строка, лишь бы не менялся
    title: 'Интерстеллар',     // что написано под плиткой
    year: 2014,                // показывается под названием; можно null
    poster: 'http://…/400.jpg',// картинка плитки (примерно 400×600); можно null
    request: { id: 12345 }     // с чем звать details для этого элемента
}
```

Необязательные поля, если они у вас есть:

| Поле | Что даёт |
|---|---|
| `posterHi` | картинка покрупнее (500×750) для карточки фильма |
| `duration` | длительность **в минутах** |
| `description` | описание |
| `agelimit` | возрастное ограничение, число: `16` → на экране «16+» |
| `uhd`, `hdr` | значок на плитке: `4K`, `HDR`, `4K HDR` |

Чего писать **не надо**: рейтинг, жанры. Их плеер сам возьмёт у Кинопоиска и TMDB по названию и
году — одинаково для всех источников.

## Метод `details(item)` — карточка фильма

**Получает:** элемент, по которому кликнули (тот же объект, что вы отдали в `page`), или результат
вашего `itemById`. Обычно вам нужно только `item.request` или `item.fid`.

**Возвращает:**

```js
{
    item: { …тот же элемент, но с описанием, длительностью, крупным постером… },
    episodes: [],      // серии сериала — такие же элементы; у фильма пустой список
    streams: [         // ссылки на видео
        { id: null, name: '', url: 'http://…/film.m3u8', variants: null }
    ]
}
```

### `streams` — озвучки

Это список ссылок на **один и тот же** фильм.

**Одна ссылка** (обычный случай) — отдайте один элемент с пустым `name`, и в карточке будет обычная
кнопка «▶ Смотреть»:

```js
streams: [ { id: null, name: '', url: 'http://…/film.m3u8', variants: null } ]
```

**Несколько озвучек** — по элементу на каждую, с названием. Плеер сам нарисует кнопку на каждую:

```js
streams: [
    { id: 56,  name: 'Дубляж',     url: 'http://…/dub.m3u8' },
    { id: 111, name: 'Netflix',    url: 'http://…/netflix.m3u8' },
    { id: 232, name: '1+1studio',  url: 'http://…/1plus1.m3u8' }
]
```

На экране:

```
 ИНТЕРСТЕЛЛАР (2014)
 [ ▶ Дубляж ]   [ ▶ Netflix ]   [ ▶ 1+1studio ]
```

То же самое появится и в карточке Home Assistant. Какую озвучку выбрали — плеер запомнит сам.

### `variants` — качество

Если сервис отдаёт одно и то же видео в разном качестве, положите их в `variants` — и у зрителя
появится кнопка переключения качества:

```js
{
    id: 56, name: 'Дубляж',
    url: 'http://…/auto.m3u8',          // на случай, если качество не выбрано
    variants: {
        auto: 'http://…/auto.m3u8',
        '2160': 'http://…/2160.m3u8',
        '1080': 'http://…/1080.m3u8',
        '720':  'http://…/720.m3u8'
    }
}
```

Ключи — только такие: `auto`, `2160`, `1440`, `1080`, `720`, `480`. Нет `variants` — просто не будет
кнопки качества, это нормально.

### Сериал

У сериала в `episodes` — список серий (такие же элементы, что в `page`). Когда зритель выбирает
серию, плеер вызовет `details` **уже для этой серии** — и вот там у неё должны быть свои `streams`.

Плеер сам запоминает, на какой серии и на какой минуте остановились, и предлагает «Продолжить».

## `searchRequest(root, text)` и `filterRequest(requests)`

Обе — простые переводчики «что выбрал зритель» → «ваш `request` для `page`».

```js
searchRequest(root, text) {
    return { path: '/search', query: text };   // text — что набрали на экране
},

filterRequest(requests) {
    // requests — список request'ов выбранных пунктов фильтров из root()
    return Object.assign({ path: '/movies' }, ...requests);   // например {path:'/movies', genre:5, year:2014}
}
```

## `itemById(localId)` — самый важный для избранного

Когда зритель добавляет фильм в избранное, плеер запоминает **только его идентификатор** — ваш `fid`.
Через неделю, когда избранное открывают снова, никакого элемента уже нет, есть только этот номер.
Вот тогда и вызывается `itemById`: по номеру вернуть элемент, с которым можно звать `details`.

```js
itemById(localId) {
    return { type: 'stream', fid: String(localId), request: { id: localId } };
}
```

Никаких запросов в сеть тут делать не надо — просто соберите объект.

Этот же метод работает, когда фильм включают из карточки Home Assistant или голосом.

## Про идентификаторы

Внутри плагина вы всегда работаете со **своим** номером: `12345`.

Наружу — в избранное, в историю просмотра, в Home Assistant — плеер добавляет к нему имя источника:
`example:12345`. Это чтобы фильм №12345 из вашего источника не перепутался с фильмом №12345 из
другого. Плагину про это знать не нужно: ему всегда приходит только его собственный номер.

## Полный рабочий пример

Рядом лежит [`vod-plugin-example.js`](vod-plugin-example.js) — готовый плагин с комментариями.
Он ничего не скачивает, а отдаёт несколько придуманных фильмов: у одного три озвучки, есть сериал
из двух серий. Установите его файлом (шаги 1–2, адрес — любой) и посмотрите, как всё выглядит
на экране, не имея никакого сервиса.

А вот самый маленький плагин, который уже работает, — можно взять за основу:

```js
VodSources.register('example', {
    create(url, params) {
        const base = url.replace(/\/+$/, '');
        const api = async (path) => {
            const res = await fetch(base + path, { headers: { 'X-Api-Key': params.key || '' } });
            if (!res.ok) throw new Error('HTTP ' + res.status);
            return res.json();
        };
        // из формата сервиса — в формат плеера; это и есть вся работа плагина
        const toItem = (m) => ({
            type: m.is_series ? 'multistream' : 'stream',
            fid: String(m.id),
            title: m.name,
            year: m.release_year || null,
            poster: m.poster_url || null,
            request: { id: m.id }
        });

        return {
            async root() {
                const cats = await api('/categories');
                return {
                    categories: cats.map(c => ({ title: c.name, request: { cat: c.id, page: 1 } })),
                    search: { request: { query: '{USERINPUT}' } },
                    filters: []
                };
            },
            async page(request) {
                const q = request.query
                    ? '/search?q=' + encodeURIComponent(request.query)
                    : '/movies?cat=' + request.cat + '&page=' + (request.page || 1);
                const r = await api(q);
                return {
                    items: (r.items || []).map(toItem),
                    count: r.total || null,
                    nextRequest: r.has_more ? Object.assign({}, request, { page: (request.page || 1) + 1 }) : null
                };
            },
            async details(item) {
                const m = await api('/movies/' + (item.request ? item.request.id : item.fid));
                return {
                    item: Object.assign(toItem(m), { description: m.overview || '', duration: m.runtime || 0 }),
                    episodes: (m.episodes || []).map(toItem),
                    streams: (m.sources || [{ url: m.stream_url }]).map((s, i) => ({
                        id: s.id != null ? s.id : i,
                        name: s.dub_name || '',      // пусто — плеер покажет обычную кнопку «Смотреть»
                        url: s.url,
                        variants: s.qualities || null
                    }))
                };
            },
            searchRequest(root, text) { return { query: text }; },
            filterRequest(requests) { return Object.assign({}, ...requests); },
            itemById(localId) { return { type: 'stream', fid: String(localId), request: { id: localId } }; }
        };
    }
});
```

## Как проверить плагин, не трогая телевизор

Установите плагин и посмотрите его карточку в разделе «Плагины»: ошибок нет — файл выполнился.
Дальше откройте поиск фильмов в карточке Home Assistant: она ищет через тот же плагин в дополнении.
Если что-то не так, ошибка будет в журнале дополнения, и там видно, на каком запросе плагин споткнулся.

Если у вас есть исходники проекта, есть и готовый прогон:

```
node tools/vod-sources-test.js
```

Он проверяет реестр, установку плагина, песочницу, избранное и пример из этой инструкции; сети не
требует.

## Что плеер делает сам, а плагину делать не надо

- рисует ленты, сетку, поиск, карточку, экран рецензий;
- догружает страницы при листании;
- запоминает позицию просмотра и последнюю серию, предлагает «Продолжить»;
- ведёт избранное — общее на все телевизоры и на карточку Home Assistant;
- берёт рейтинги и жанры у Кинопоиска и TMDB по названию и году;
- переключает качество и озвучку;
- включает фильм голосом и из карточки Home Assistant;
- переводит интерфейс на четыре языка.

От плагина нужно только одно: аккуратно перевести ответы вашего сервиса в формат из этой инструкции.
